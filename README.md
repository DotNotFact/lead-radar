# Lead Radar

Персональная система поиска заказов и управления действиями для .NET-разработчика
(фриланс + удалённая работа). Следит за hh.ru, Kwork, Telegram-чатами и RSS-фидами,
оценивает релевантность и присылает в приватный Telegram-канал только то, что стоит
внимания. Плюс ежедневный бриф с очередью действий и эскалацией просроченного.

**Система только читает и уведомляет.** Никаких автоматических откликов, сообщений или
комментариев заказчикам — это всегда делает человек руками.

## Быстрый старт

```powershell
.\setup.ps1
```

Создаст `.venv`, поставит зависимости, скопирует `.env.example` → `.env`, применит миграции БД.

Дальше:

1. Откройте `.env` и заполните то, что помечено пустым (подробности — в разделе
   [«Что нужно заполнить»](#что-нужно-заполнить-перед-первым-полным-запуском) ниже).
2. Настройте профиль бота в Telegram (команды, описание):
   ```powershell
   .venv\Scripts\python.exe -m scripts.setup_bot
   ```
3. Запустите:
   ```powershell
   .\run.ps1
   ```

Для автозапуска при входе в Windows — `scripts\install_windows_task.ps1` (см. подсказки внутри
файла). Для Linux — шаблон `scripts\lead-radar.service`.

## Что нужно заполнить перед первым полным запуском

`BOT_TOKEN` уже стоит в `.env`. Остальное — вручную:

| Что | Где взять |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | [my.telegram.org](https://my.telegram.org), для **отдельной** симки, не основного аккаунта |
| `CHANNEL_ID` | Создать приватный Telegram-канал, добавить туда бота администратором, узнать numeric id (например, через [@userinfobot](https://t.me/userinfobot) или пересылкой сообщения из канала боту) |
| Список Telegram-чатов | `config/sources.yaml` → `telegram.chats` — собрать 60–100 штук поиском по «фриланс заказы», «работа программисту», «удалёнка IT», «C# вакансии»; затем `telegram.enabled: true` |
| Порог скоринга, бюджеты, время брифа | Дефолты уже стоят в `.env` / `config/keywords.yaml` — подправьте под себя |

Источники `hh_ru`, `kwork_projects`, `kwork_catalog`, `rss_remote_jobs` уже `enabled: true` и
работают без доп. настройки.

Первый запуск Telethon (Telegram-коллектора) потребует один раз интерактивно ввести код из
Telegram прямо в консоли — после этого появится файл сессии `*.session` (он в `.gitignore`,
никогда не коммитится).

## Команды бота

| Команда | Что делает |
|---|---|
| `/brief` | Бриф на сегодня: действия, просроченное (с эскалацией), итоги суток, здоровье источников |
| `/stats [7d\|30d]` | Конверсия по источникам, распределение бюджетов |
| `/export [дней]` | Обезличенный CSV-файл в чат (по умолчанию 30 дней) |
| `/sources` | Статус всех источников |
| `/health` | Диагностика источников |
| `/pause` / `/resume` | Приостановить / возобновить сбор лидов |
| `/addchat @handle` | Добавить Telegram-чат для мониторинга |
| `/todo текст` | Добавить задачу в очередь действий |
| `/done id` | Отметить задачу выполненной |
| `/snooze id дней` | Отложить задачу |

Под каждым уведомлением о лиде — кнопки **Открыть** / **Ответил** / **Мимо** (пишут исход в БД
для последующей статистики).

## Разовые прогоны источников

Полезно для проверки/наполнения БД до первого полного запуска:

```powershell
.venv\Scripts\python.exe -m scripts.collect_hh
.venv\Scripts\python.exe -m scripts.collect_rss
.venv\Scripts\python.exe -m scripts.collect_kwork
```

## Тесты и типизация

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m mypy
```

## Структура проекта

```
src/
  core/        конфиг, БД, модели, HTTP-ретрай, общий конвейер скоринга
  collectors/  по одному модулю на источник (hh.ru, Telegram, Kwork, RSS)
  scoring/     парсинг бюджета, скоринг, дедупликация
  actions/     очередь действий, ежедневный бриф
  notifier/    формат уведомлений, отправка, алерты здоровья источников
  control/     Telegram-бот (aiogram)
  export/      анонимизация, экспорт CSV, статистика
  main.py      точка входа: планировщик + Telegram + бот
scripts/       разовые прогоны источников, настройка бота, автозапуск
config/        sources.yaml, keywords.yaml, actions.yaml — вся настройка без правки кода
migrations/    версионированные SQL-миграции
tests/         pytest + pytest-asyncio, mypy --strict
```

Подробности архитектуры, инвариантов и истории решений — в [CLAUDE.md](CLAUDE.md).

## Известные ограничения

- Kwork можно опросить только по первой странице каждого раздела — `robots.txt` явно запрещает
  параметр `?page=`.
- FL.ru и Хабр Фриланс не парсятся вообще — их `robots.txt` прямо запрещает то, что нужно было
  бы читать. Ручной режим, как и Avito.
- Анонимизация имён в экспорте — эвристика по сигнальным фразам («меня зовут», «заказчик:»),
  не полноценное распознавание именованных сущностей. Имя без такой фразы не будет вырезано.
