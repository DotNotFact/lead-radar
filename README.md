# Lead Radar

Персональная система поиска заказов и управления действиями для .NET-разработчика
(фриланс + удалённая работа). Следит за hh.ru, Kwork, RemoteOK, Freelancer.com,
Telegram-чатами и RSS-фидами, оценивает релевантность и присылает в приватный Telegram-канал
только то, что стоит внимания. Плюс ежедневный бриф с очередью действий и эскалацией
просроченного, отдельная метка "это может закрыть ИИ" и экспорт таких лидов готовым текстом
для внешнего ИИ.

**Система только читает и уведомляет.** Никаких автоматических откликов, сообщений или
комментариев заказчикам: это всегда делает человек руками.

## Быстрый старт

```powershell
.\setup.ps1
```

Создаст `.venv`, поставит зависимости, скопирует `.env.example` → `.env`, применит миграции БД.

Дальше:

1. Откройте `.env` и заполните то, что помечено пустым (подробности в разделе
   [«Что нужно заполнить»](#что-нужно-заполнить-перед-первым-полным-запуском) ниже).
2. Настройте профиль бота в Telegram (команды, описание):
   ```powershell
   .venv\Scripts\python.exe -m scripts.setup_bot
   ```
3. Запустите:
   ```powershell
   .\run.ps1
   ```

Для автозапуска при входе в Windows: `scripts\install_windows_task.ps1` (см. подсказки внутри
файла). Для Linux: шаблон `scripts\lead-radar.service`.

## Что нужно заполнить перед первым полным запуском

`BOT_TOKEN` уже стоит в `.env`. Остальное заполняется вручную:

| Что | Где взять |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | [my.telegram.org](https://my.telegram.org), для **отдельной** симки, не основного аккаунта |
| `CHANNEL_ID` | Создать приватный Telegram-канал, добавить туда бота администратором, узнать numeric id (например, через [@userinfobot](https://t.me/userinfobot) или пересылкой сообщения из канала боту) |
| Список Telegram-чатов | `config/sources.yaml` → `telegram.chats`: собрать 60–100 штук поиском по «фриланс заказы», «работа программисту», «удалёнка IT», «C# вакансии»; затем `telegram.enabled: true` |
| Порог скоринга, бюджеты, время брифа | Дефолты стоят в `.env` / `config/keywords.yaml`, но менять их проще прямо в боте: `/settings` или кнопка ⚙️ в `/menu`, без правки файлов и перезапуска |
| `HH_CLIENT_ID`, `HH_CLIENT_SECRET`, `HH_REDIRECT_URI` | Опционально, для отслеживания собственных откликов на hh.ru. Зарегистрировать приложение на [dev.hh.ru/admin](https://dev.hh.ru/admin) (тип «Веб»), затем `python -m scripts.hh_oauth_login`, который впишет `HH_ACCESS_TOKEN`/`HH_REFRESH_TOKEN` сам |
| `FREELANCER_OAUTH_TOKEN` | Опционально, для источника `freelancer` (заказы с зарубежных клиентов). Личный токен, не ключ приложения: [accounts.freelancer.com/settings/develop](https://accounts.freelancer.com/settings/develop) → Sandbox/Live token. После заполнения переключить `freelancer.enabled: true` в `config/sources.yaml` |
| `MINIAPP_OWNER_TELEGRAM_ID` | Опционально, для Telegram Mini App (см. ниже): ваш numeric Telegram id, например через [@userinfobot](https://t.me/userinfobot). Без него Mini App не стартует |

Источники `hh_ru`, `kwork_projects`, `kwork_catalog`, `rss_remote_jobs`, `remoteok` уже
`enabled: true` и работают без доп. настройки. У `freelancer` `enabled: false`, пока не
заполнен `FREELANCER_OAUTH_TOKEN`.

Первый запуск Telethon (Telegram-коллектора) потребует один раз интерактивно ввести код из
Telegram прямо в консоли, после этого появится файл сессии `*.session` (он в `.gitignore`,
никогда не коммитится).

## Команды бота

`/start` или `/menu` открывают меню кнопками, все разделы ниже доступны без ввода команд
руками (📋 Бриф, 📊 Статистика, 🏢 CRM, 💰 Доход, 🤖 ИИ-лиды, 📝 Шаблоны, 🔧 Источники,
⚙️ Настройки, ❓ Помощь). `/help` даёт тот же список команд текстом.

| Команда | Что делает |
|---|---|
| `/brief` | Бриф на сегодня: действия, просроченное (с эскалацией), итоги суток, здоровье источников |
| `/stats [7d\|30d]` | Конверсия по источникам, распределение бюджетов |
| `/ai_leads` | Лиды, помеченные как выполнимые целиком с помощью ИИ (критерии в `config/keywords.yaml` → `ai_assistable`) |
| `/export [дней]` | Обезличенный CSV-файл в чат (по умолчанию 30 дней) |
| `/export_ai [дней]` | Только ИИ-лиды, обычным текстом с промптом-инструкцией впереди, готово вставить в чат с ИИ |
| `/sources` | Статус всех источников |
| `/health` | Диагностика источников |
| `/pause` / `/resume` | Приостановить / возобновить сбор лидов |
| `/addchat @handle` | Добавить Telegram-чат для мониторинга |
| `/todo текст` | Добавить задачу в очередь действий |
| `/done id` | Отметить задачу выполненной |
| `/snooze id дней` | Отложить задачу |
| `/crm` | Список компаний в работе (простой CRM) |
| `/crm_add название` | Добавить компанию, сразу ставит первое напоминание о касании на сегодня |
| `/crm_touch id дней [результат]` | Записать результат касания, закрыть текущее напоминание, поставить следующее через N дней |
| `/crm_status id статус` | Сменить статус (`new`/`contacted`/`negotiating`/`won`/`lost`/`on_hold`) |
| `/income сумма [заметка]` | Записать поступление (сегодняшним числом) |
| `/goal сумма` | Задать цель дохода на месяц, появляется в ежедневном брифе |
| `/templates` | Список шаблонов первого ответа |
| `/template имя` | Получить текст шаблона для копирования |
| `/prompts` | Список промптов для внешнего ИИ (профиль на бирже, доводка черновика ответа и т.п.) |
| `/prompt имя` | Получить текст промпта для копирования |
| `/hh_status` | Статусы собственных откликов на hh.ru (нужен настроенный OAuth, см. выше) |
| `/settings` | Текущие значения порога уведомления, минимального бюджета, времени брифа |
| `/set_threshold число` | Порог уведомления, действует сразу, без перезапуска |
| `/set_budget_floor число` | Минимальный бюджет для скоринга, действует сразу |
| `/set_brief_time ЧЧ:ММ` | Время ежедневного брифа, переставляет задачу планировщика на лету |

Под каждым уведомлением о лиде есть кнопки **Открыть** / **Ответил** / **Мимо** (пишут исход в БД
для последующей статистики). Напоминания о касаниях компаний в CRM идут через ту же очередь
действий, что и обычные задачи: попадают в `/brief`, эскалируются при откладывании 3+ раз.

## Структура проекта

```
src/
  core/        конфиг, БД, модели, HTTP-ретрай, общий конвейер скоринга
  collectors/  по одному модулю на источник (hh.ru, Telegram, Kwork, RSS, hh.ru-отклики)
  scoring/     парсинг бюджета, скоринг, дедупликация
  actions/     очередь действий, ежедневный бриф (+ доход/цель месяца)
  crm/         компании, касания (переиспользует очередь actions)
  notifier/    формат уведомлений, отправка, алерты здоровья источников и откликов hh.ru
  control/     Telegram-бот (aiogram): команды, инлайн-меню (menu.py), шаблоны/промпты
  export/      анонимизация, экспорт CSV/JSONL/текст для ИИ, статистика
  main.py      точка входа: планировщик + Telegram + бот
scripts/       разовые прогоны источников, OAuth-логин hh.ru, настройка бота, автозапуск
config/        sources.yaml, keywords.yaml, actions.yaml: вся настройка без правки кода
migrations/    версионированные SQL-миграции
tests/         pytest + pytest-asyncio, mypy --strict
```

## Mini App

Telegram Mini App (React + TypeScript, `miniapp/`): веб-интерфейс поверх бота, открывается
кнопкой прямо в чате. Первая итерация: экран источников со статусом здоровья и переключателем
вкл/выкл. План остальных экранов и технические ограничения смотрите в `docs/miniapp-brief.md`,
инструкции по разработке и сборке фронтенда в `miniapp/README.md`.

Бэкенд (`src/webapp`), часть основного процесса, стартует вместе с `python -m src.main`, если
в `.env` заполнен `MINIAPP_OWNER_TELEGRAM_ID` (см. таблицу выше); без него просто не поднимается,
остальной бот продолжает работать.

## Архитектура и принципы

- Система только читает и уведомляет. Никаких автоматических откликов, сообщений или
  комментариев заказчикам: исходящий контакт всегда делает человек руками.
- Секреты только в `.env` (`*.session`, `*.db` тоже в `.gitignore`), токены и ключи никогда
  не попадают в лог.
- Для чтения чатов используется отдельный Telegram-аккаунт, не основной; юзербот не вступает в чаты
  программно, не меняет профиль, не пишет от своего имени.
- Вежливый парсинг источников без официального API: не чаще 1 запроса в 10 секунд на домен,
  честный User-Agent с контактом, `robots.txt` соблюдается, а не обходится.
- Экспорт лидов всегда обезличен: телефоны, email, @username, имена вырезаются перед
  выгрузкой (см. «Известные ограничения» ниже про точность этой эвристики).
- Деградация вместо падения: смерть одного источника не роняет систему, источник помечается
  `degraded`, остальное продолжает работать.
- Никаких обходов защиты: капч, поддельных сессий, чужих аккаунтов. Источник, который не
  даётся (запрещён `robots.txt` или технически заблокирован), переводится в ручной режим, а не
  взламывается; подробнее см. FL.ru/Хабр Фриланс/Upwork/Remotive.io ниже.

## Известные ограничения

- Kwork можно опросить только по первой странице каждого раздела: `robots.txt` явно запрещает
  параметр `?page=`.
- FL.ru и Хабр Фриланс не парсятся вообще: их `robots.txt` прямо запрещает то, что нужно было
  бы читать. Ручной режим, как и Avito.
- Upwork и Remotive.io по той же причине не подключены: у Upwork нет публичного API поиска
  проектов (отключён ещё в середине 2010-х) и сам `robots.txt` отдаётся через bot-challenge;
  Remotive.io в `robots.txt` явно запрещает `/api/*`, а весь их фид отдаётся именно оттуда.
- У Freelancer.com поля ответа взяты по документации API, не сверены на живом токене (нет
  доступа к личному аккаунту владельца). Если структура на практике другая, отсутствующие
  поля останутся `None`, источник корректно уйдёт в `degraded`, а не уронит процесс, но стоит
  свериться на первом реальном прогоне с заполненным `FREELANCER_OAUTH_TOKEN`.
- Анонимизация имён в экспорте работает по эвристике: сигнальные фразы («меня зовут», «заказчик:»),
  а не полноценное распознавание именованных сущностей. Имя без такой фразы не будет вырезано.
- Отслеживание откликов на hh.ru построено по документации API (нет доступа к личному
  OAuth-токену для живой проверки), поля ответа `/negotiations` стоит свериться на первом
  реальном прогоне; при расхождении источник корректно уходит в degraded, а не падает.
- Список Telegram-чатов в `sources.yaml` собран автоматически из открытых статей-подборок,
  не проверен вручную, почистите под себя (подробности в комментарии над списком в файле).
